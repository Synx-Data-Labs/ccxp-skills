# T20261109-243837: ccxp-hud CI cell: ETA for a running workflow

## Problem

- **Type**: feature
- The CI cell shows `◐ running` with no hint of when the run should finish; the owner asked "anyway to put a ETA in?".
- Wanted: run start plus the median duration of the last completed successful runs of the same workflow (same event preferred), from the one `gh run list` call the helper already makes.
- Display `ETA HH:MM` (local time), `~HH:MM` with a wide spread, `over usual (Nh)` when overdue, nothing under 3 runs of history.
- Config key `ci.eta` (default on), documented in `hud/README.md`; tests with fixture runs, no network.

## Closed

- Shipped in PR #643 (claim PR #642). No version bump; suggested next version 6.4.0 (user-visible feature).
- Helper (`hud/scripts/hud-ci.sh`): one `gh run list --limit 20` call replaces `--limit 1`; the newest run is the state, older successful runs of the same event (else any event, at least 3, at most 7) give the median, min and max duration. `eta` is only set while the newest run is `in_progress`.
- Display (`hud/model.ts` `ciEta`): `ETA 18:40` (spread at most half the median), `ETA 14:20-19:05` (wider), `+1d` on another day, `over usual (4h)` when overdue, nothing under 3 runs of history. Config `ci.eta: false` turns it off.
- Tests: `tests/hud_ci.bats` (10 new, run in CI); `hud/pure.test.ts` (7 new) need the Claude Code runner, so CI does not run them; they were run locally through a `node:test` shim (all pass; the 5 shim-only failures are identical on main).
- Not done: showing the running job or stage name (needs a second call per run); a live-HUD eyeball after the plugin update.
