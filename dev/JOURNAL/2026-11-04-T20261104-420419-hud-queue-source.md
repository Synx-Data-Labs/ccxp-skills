# T20261104-420419: HUD queue source: default branch instead of the current clone

- **Problem**: the queue cell and its claimed/revisited/auto-parked counts read `dev/TODO` from the clone's working tree. A clone 72 commits behind origin showed 12 claimed where origin/main had 6.
- **Built**:
  - Config key `queue: { source: "working-tree" | "default-branch" }`; unset keeps the working tree, so existing users see no change. A project file overrides the user file like `ci`.
  - `default-branch` mode reads `origin/<default>` with git object reads only (`git archive` into a temp dir); no checkout, no working-tree write. Same buckets and counts, same claimed rule.
  - Freshness: detached `git fetch origin <default>` at most every 2 minutes, 15 s timeout, no credential prompt, silent offline.
  - No usable origin ref: falls back to the working tree and marks it (`queue@wt`).
  - Label: `queue@main 44 = ...` in the band, `queue (main) 44 = ...` in `/hud details`.
  - `/hud config` has a fourth question, "Queue source" (header within the 12-character limit), recommending the default branch; `/hud config <url>` unchanged.
- **Tests**: `tests/hud_queue_source.bats` (fixture repo with a bare origin: stale vs newer, trunk default, no-origin fallback, offline, no working-tree writes, fetch rate limit, `queue_source` stdin), `hud/configure.test.ts`, `hud/pure.test.ts`, `tests/hud_config.bats`.
- **Docs**: `hud/README.md` (config table, Queue cell, `/hud config`, details).
