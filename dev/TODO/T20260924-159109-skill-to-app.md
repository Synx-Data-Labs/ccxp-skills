# T20260924-159109: Design /skill-to-app — compile a matured skill's deterministic steps into a program

## Problem

- **Type**: feature
- A mature, stable skill (fixed control-flow, low-branching, deterministic
  steps) still pays LLM-token cost every invocation to re-read and
  re-interpret its full `SKILL.md` instructions, even for the parts that
  never actually require judgment.
- Idea: a `/skill-to-app` skill that takes a matured skill's instructions
  and offloads the deterministic/procedural logic to a compiled script or
  small program, reserving the model's token budget for the genuinely
  flexible, judgment-requiring parts of the skill.
- Open questions to resolve during design:
  - What makes a skill "mature" enough to compile — stability bar, how much
    branching is acceptable, who decides.
  - How the compiled app stays in sync when the source `SKILL.md` changes
    (drift risk between the doc and the generated code).
  - Whether this looks like the existing `Workflow` tool's scripting model
    (`agent()`/`parallel()`/`pipeline()`), a plain shell/Python script per
    skill, or something skill-authoring-specific.
  - How the compiled app hands back control to the model for the parts that
    can't be compiled (judgment calls, open-ended synthesis) — the interface
    between "program" and "flexible" halves.
  - Relationship to `skill-conventions` (does this become a documented
    pattern there, or a separate lifecycle stage after a skill matures).
