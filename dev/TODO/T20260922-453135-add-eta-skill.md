# T20260922-453135: Add `/eta` skill — estimate time-to-completion for the current task on hand

## Problem

- **Type**: feature
- No existing skill reports "when will the current task likely be done" — a
  user mid-`/drive`/`/claim` session has no quick way to see this without
  manually reading the task file's `estimation:` and doing date math
  themselves.
- Maintainer ask (this conversation, 2026-09-22): a `/eta` skill that
  estimates time-of-finishing the current task, computing a projected
  finish time from the task's `estimation:` frontmatter and elapsed time so
  far, and defaulting to the local system timezone (optionally overridable
  to a different timezone).
- Basis for the estimate (maintainer-specified): the task's own
  `estimation:` field plus elapsed time since work started (not just a
  static "now + remaining estimation" with no elapsed-time awareness).
- Done looks like: `/eta` (no argument) identifies the current task (the
  one this clone holds via `claimed_by`, or an explicit `T<id>` argument),
  reads its `estimation:` and a start-time signal, computes elapsed vs.
  remaining, and reports a projected finish time in the local system
  timezone by default — with an optional argument to report in a different
  timezone instead.
- **`claimed_by` itself carries no timestamp** (verified against
  `_session/task_claim.sh:521-539` — `_tc_acquire` only ever writes the
  claimant identity string, never a time) — so the "start time" has to come
  from somewhere else: the git commit timestamp of whichever commit set
  `claimed_by` on this task (every task pickup in this repo's convention
  lands a dedicated claim PR first, so that commit's timestamp is a
  reliable proxy for "when work started"), found via
  `git log -S"claimed_by: <claimant-id>" --format=%aI -- <task-file>` (last
  match). Design phase should confirm this holds for every pickup path
  (`/drive` Phase 1, `/claim`, `/address-pr`'s `free`-verdict claim) before
  committing to it.
- **Known bypass this derivation doesn't cover**: `drive/SKILL.md`'s
  `CCXP_PEER_MODE=0` opt-out (verified — line 116) flips only `status:`
  on claim, never touching `task_claim.sh`/`claimed_by` at all — so a repo
  running with peer mode disabled would have no `claimed_by`-setting commit
  for the `git log -S` search to find, and this start-time derivation
  silently returns nothing. `/eta` needs an explicit fallback for that case
  (e.g. the claim-branch's first commit by name convention, or just report
  "start time unknown, showing remaining estimation only") rather than
  failing silently.

## Context

- `_session/task_claim.sh` already tracks `claimed_by`/`claimed_role` per
  task — the source for "which task is current," but not "when did work
  start" (no timestamp field exists; see the Problem section's note on
  deriving start-time from the claim commit instead).
- `repo-conventions/templates/task.md`'s `estimation:` field
  (`15m|30m|1h|2h|4h|1d|2d|1w`) is the existing bucketed-estimate schema
  this skill should read, not reinvent.
