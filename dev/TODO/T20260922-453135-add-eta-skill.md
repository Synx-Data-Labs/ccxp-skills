# T20260922-453135: Add `/eta` skill — estimate time-to-completion for the current task on hand

## Problem

- **Type**: feature
- No existing skill reports "when will the current task likely be done" — a
  user mid-`/drive`/`/claim` session has no quick way to see this without
  manually reading the task file's `estimation:` and doing date math
  themselves.
- Maintainer ask (this conversation, 2026-09-22): a `/eta` skill that
  estimates time-of-finishing the current task, computing a projected
  finish time from the task's `estimation:` frontmatter and elapsed time so
  far, and defaulting to the local system timezone (optionally overridable
  to a different timezone).
- Basis for the estimate (maintainer-specified): the task's own
  `estimation:` field plus elapsed time since work started (not just a
  static "now + remaining estimation" with no elapsed-time awareness).
- Done looks like: `/eta` (no argument) identifies the current task (the
  one this clone holds via `claimed_by`, or an explicit `T<id>` argument),
  reads its `estimation:` and a start-time signal (`claimed_by` claim time
  / first commit on its branch), computes elapsed vs. remaining, and
  reports a projected finish time in the local system timezone by default
  — with an optional argument to report in a different timezone instead.

## Context

- `_session/task_claim.sh` already tracks `claimed_by`/`claimed_role` per
  task — likely the source for "which task is current" and "when did work
  start."
- `repo-conventions/templates/task.md`'s `estimation:` field
  (`15m|30m|1h|2h|4h|1d|2d|1w`) is the existing bucketed-estimate schema
  this skill should read, not reinvent.
